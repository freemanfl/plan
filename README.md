# Web studio

This is a studio that makes websites for small businesses.

The physical product is a good-looking, modern, fast site or landing page. The thing actually being sold is that the site exists, it looks professional, it works, and someone remains responsible for ordinary changes. The client should not have to manage hosting, code, or plugins.

This is not a custom agency and not a DIY builder. The bet is a repeatable pipeline: messy client material in, a credible site out, then a short human pass so it looks good. Similar studios already exist. The idea is raw and the market is crowded. That is accepted. The work is to make this version run.

These four files are the current system:

- This file — what we are doing and why.
- [Production pipeline](production-pipeline.md) — how a site is produced.
- [Maintenance](maintenance.md) — looking after the live site.
- [References](references.md) — which sites teach structure and style.

Older material is in `Archive/`. It is not a source of truth.

## How a site is made

1. **Gather.** Take everything the client already has: answers, an old site, Google listing, Instagram, photos, videos, PDFs, a logo. Do not wait for a perfect brief.
2. **Normalize.** AI does the first cleanup: fix text, pull facts into a standard pack, resize and crop images, reject unusable assets, list holes. A human checks facts and decides what to ask for, generate, or skip. Later steps see this pack, not the raw dump.
3. **Structure.** AI proposes sections and order from the pack plus client-site references in the matching category (plumber, restaurant, studio, and so on). References teach how that kind of business is explained, not how to copy a brand.
4. **Style.** A second AI pass on the locked outline: type, spacing, color, image treatment, cards, buttons. Same references, different question: how it should feel.
5. **Elevate.** A short human pass so the result actually looks good. Crop, spacing, hero, kill anything cheap. Time-boxed. If this regularly becomes a full custom-design day, the pipeline is not working.

The steps, inputs, and outputs are in [production-pipeline.md](production-pipeline.md).

## After launch

Creating the site and looking after it are separate. The offer includes remaining responsible for ordinary changes so the client does not run the website themselves. That loop is in [maintenance.md](maintenance.md). It does not belong inside the five production steps.

## The pack

Normalize produces a minimal, standard set of info and assets for a website. The exact contents are not defined yet. Distill them from the [client-site references](references.md): whatever those sites actually need in order to work — copy, facts, and media — in the smallest form that still lets structure and style run.

Do not invent extra fields or rules before that distillation.

## Two kinds of references

**Client sites** teach how to build a plumber, restaurant, studio, tutor, or barber page. They are local-business scale. There are about ten per category. A job uses several from the matching row, not the whole list.

**Studio / offer sites** teach how this studio sells. They are not used to generate client pages:

- Oak Harbor — peace of mind, service funnel, small-business positioning
- Build 76 — closest analogue: look after the site for local clients
- ShipFast — persuasion order only, not SaaS visuals or density

The lists and how to use them are in [references.md](references.md).

## What this is not yet

Pricing, legal entity, and client acquisition are real, but they are not the production pipeline. Do not expand those here until a site has been produced from a fake local business using only public information.

Do not add layout libraries, effects catalogues, or extra process docs. If something must be written, update one of these four files.
